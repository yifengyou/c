# OllyDbg 动态调试

> OllyDbg 是 32 位 Windows 逆向的经典动态调试器（用户态、免安装、插件生态庞大）——滴水教程的主力工具。动态=让程序真跑起来，在关键处停下来看现场。简介见 [OllyDbg简介](OllyDbg/OllyDbg简介.md)。

## 静态vs动态：为什么两个都要

| | 静态（IDA） | 动态（OD） |
| --- | --- | --- |
| 程序跑不跑 | 不跑 | 真跑 |
| 看到什么 | **全部代码**（含永不执行的） | 实际走过的路径+**运行时的值** |
| 拿手好戏 | 逻辑全景、算法还原 | 断点看内存/改寄存器/跟踪解密结果 |
| 弱点 | 分不清哪条路真被执行 | 被反调试戏弄、路径覆盖不全 |

**实战是交替进行**：IDA看到 `strcmp` → OD断在 `strcmp` 返回处 → 看比较结果 → 决定patch点。

## OD四窗格（对照本库知识）

```text
┌────────────────────────────────────────────┐
│ 反汇编窗格（CPU主窗）                        │
│   就是你 [跳转指令集](../汇编/跳转指令集.md) │
│   学的指令 + 跳转箭头（红=不跳 绿=跳）        │
├──────────────┬─────────────────────────────┤
│ 寄存器窗格    │ 内存dump窗格                  │
│ [通用寄存器]  │ [内存读写·走廊模型]           │
│ 右键改值      │ 按地址翻内存/看字符串          │
├──────────────┴─────────────────────────────┤
│ 栈窗格：[堆栈图](../汇编/堆栈图.md) 活体现场   │
│ esp附近：返回地址/参数/局部变量               │
└────────────────────────────────────────────┘
```

## 必会操作（与crackme流程对应）

| 操作 | 快捷键 | 用途 | 本库对应 |
| --- | --- | --- | --- |
| 下断点 | `F2` | 停在选定指令 | crackme01断在 strcmp 返回处 |
| 运行 | `F9` | 跑到断点/结束 | —— |
| 单步（进函数） | `F7` | 跟进 call | 观察[函数栈帧](../汇编/堆栈图.md)建立 |
| 单步（过函数） | `F8` | call当一步 | 主力单步 |
| 执行到返回 | `Ctrl+F9` | 跑完当前函数 | 看strcmp返回值 |
| 改EAX/标志 | 寄存器窗格双击 | 直接改比较结果 | "当场让ZF=1"——crackme的动态版解法 |
| 改内存字节 | `Ctrl+E` | 汇编窗内改指令 | **jne→nop/jmp 的可视化版**（[crackme01补丁](../crackme/crackme01/crackme01.md)） |
| 查看跳转将跳否 | 跳转箭头颜色 | 红/绿 | jcc的"读灯"预演（[EFLAGS](../汇编/EFLAGS寄存器.md)） |
| 命令行插件 | —— | `bp printf` 式下断 | 类似gdb的break |

## 动态破解三式（crackme01在OD里的三种死法）

```text
① 断在strcmp返回 → 手改EAX=0（相等）→ F9 → Congratulations（改寄存器流）
② 断在test后的jne → 选中按Enter翻转/空格改jmp → F9（改指令流）
③ 观察rsi指向的"WaterDrop2026" → 白嫖密码（看内存流）
```

## x64dbg：OD的精神续作

OD 原版止步 32 位；**x64dbg** 是开源继任者（支持x64、UI相似、持续更新）。概念完全通用：F2/F9/F8、四窗格、插件——本页操作表照搬即可。

> 本库实测环境是 Linux：gdb 就是"Linux上的OD"——`b *addr`（断点）、`ni/si`（单步）、`set $eax=0`（改寄存器）、`x/16bx addr`（dump内存）一一对应。各实战篇用的正是这套。
