# 枚举类型

## 基本用法

枚举把一组**整数常量**起名打包，提高可读性：

```c
enum Color { RED, GREEN, BLUE };      /* 默认从0开始：RED=0, GREEN=1, BLUE=2 */

enum Color c = GREEN;
if (c == GREEN) printf("绿色\n");
```

可指定值：

```c
enum Level {
    DEBUG = 0,
    INFO  = 1,
    WARN  = 30,
    ERROR = 40,       /* 未指定的接着上一个+1 */
    FATAL             /* = 41 */
};

enum { A = 1, B = 2, C = 4, D = 8 };  /* 无名枚举当常量集合用 */
```

## 枚举的本质

**枚举常量就是 int 常量**，枚举变量是能装下这些值的整型变量：

```c
enum Color c = 0;          /* 0 就是 RED，类型宽松（老代码常态） */
enum Color d = 100;        /* 多数编译器不报错！枚举不做范围检查 */
printf("%d\n", GREEN);     /* 1：枚举常量可直接当整数用 */
```

```c
/* 上面代码等价于 —— 编译器眼里的真实形态 */
#define RED   0
#define GREEN 1
#define BLUE  2
int c = 1;
```

## 枚举 vs #define

| 对比 | enum | #define |
| --- | --- | --- |
| 调试器可见？ | ✔ 显示名字（gdb中 `p Color::GREEN`） | ✘ 预处理期消失 |
| 类型关联 | 语义上成组（enum Color） | 散落的魔法数字 |
| 自动编号 | ✔ 依次+1，插入新值不用手改 | ✘ 全手动 |
| 能否用于数组大小/switch | ✔ 常量表达式 | ✔ |
| 能否用于预处理 `#if` | ✘（预处理在编译前） | ✔ |

```c
/* enum 的成组性带来的经典模式： */
enum State { STATE_IDLE, STATE_RUN, STATE_ERR, STATE_MAX };
/* STATE_MAX 作为"哨兵"自动=成员个数 */

const char *names[STATE_MAX] = { "idle", "run", "err" };  /* 表驱动：名字表 */
void handle(enum State s)
{
    if (s >= STATE_MAX) return;      /* 范围检查 */
    printf("%s\n", names[s]);        /* 值→名字（日志友好） */
}
```

## switch + enum：黄金搭档

```c
enum Command { CMD_START, CMD_STOP, CMD_RESET };

void dispatch(enum Command cmd)
{
    switch (cmd) {
    case CMD_START: start();  break;
    case CMD_STOP:  stop();   break;
    case CMD_RESET: reset();  break;
                    /* 不写default：gcc -Wall 会在新增枚举值时警告漏分支！ */
    }
}
```

这是C语言实现**状态机/命令分发**最清晰的方式。

## 位标志枚举（flags 模式）

```c
enum Perm {
    PERM_READ  = 1 << 0,   /* 0001 */
    PERM_WRITE = 1 << 1,   /* 0010 */
    PERM_EXEC  = 1 << 2    /* 0100 */
};

int perm = PERM_READ | PERM_WRITE;              /* 组合：0011 */

if (perm & PERM_WRITE) { }                      /* 测试某位 */
perm |= PERM_EXEC;                              /* 添加 */
perm &= ~PERM_READ;                             /* 移除 */
```

> 类似 Linux 的 `O_RDWR|O_CREAT`、`PROT_READ|PROT_WRITE`，本质都是位标志组合。展开原理见[位运算](位运算.md)。

## 陷阱

```c
/* 1. 重复值 */
enum E { A = 1, B = 1 };       /* 合法！但 switch 两个case会冲突 */

/* 2. 枚举变量赋非枚举值无检查 */
enum Color c = 99;             /* 编译器通常不报错（C比C++宽松得多） */

/* 3. 跨类型比较 */
enum Color c = RED;
int x = 0;
c == x;                        /* 恒成立（都是int语义），但语义上可疑 */
```

## C23 增强速览

```c
enum E : uint8_t { A, B, C };   /* C23：可指定底层类型 */
```

详见[C标准演进](C标准演进.md)。

## 实战：编译提取汇编逐行解析（真实输出）

> 以下汇编全部为**真实编译产物**，指令逐字来自 gcc 输出，`;` 注释为整理所加。提取流程见 `.opencode/skills/c-dev/SKILL.md`；环境噪音说明见[数组·实战](数组.md)。
> 实测环境：Ubuntu 24.04 / gcc 13.3.0 / x86-64（System V ABI）/ Intel 语法

### 实验1：枚举在汇编里只剩立即数

```c
enum Level { DEBUG = 0, INFO = 1, WARN = 30, ERROR = 40, FATAL };

int is_error(enum Level lv)
{
    return lv == ERROR;          /* ERROR = 40 */
}
int main(void)
{
    return is_error(FATAL);      /* FATAL=41，41==40 → 0 → 实测退出码0 ✔ */
}
```

```asm
is_error:
    endbr64
    push    rbp
    mov     rbp, rsp
    mov     DWORD PTR -4[rbp], edi     ; 参数lv（一个普通int）
    cmp     DWORD PTR -4[rbp], 40      ; ★ERROR → 立即数40
    sete    al                          ; 相等置1
    movzx   eax, al
    pop     rbp
    ret

main:
    endbr64
    push    rbp
    mov     rbp, rsp
    mov     edi, 41                     ; ★FATAL → 立即数41（自动接续40+1）
    call    is_error
    pop     rbp
    ret
```

汇编里**找不到任何"枚举"的痕迹**：`ERROR` 变成立即数 40、`FATAL` 变成立即数 41（`FATAL` 未显式赋值，接续 `ERROR=40` 自动 +1——这条规则直接体现在编译产物里）。枚举的全部价值都在编译期（可读性、调试器符号、switch漏分支检查），运行期它就是 int：

| 你写的 | 编译器看到的 | 机器里的 |
| --- | --- | --- |
| `enum Level lv` | `int lv` | edi 寄存器 |
| `lv == ERROR` | `lv == 40` | `cmp ..., 40` |
| `return FATAL;` | `return 41;` | `mov edi, 41` |

> 逆向提示：gdb 里 `print FATAL` 能显示 41（调试信息里有枚举表），但机器码里只有立即数——**"改枚举值不改汇编行为，但会破坏二进制兼容"**（两个模块用不同枚举值通信时是经典事故）。

## 小结

1. 枚举 = 整数常量的成组命名，本质是int，**不做运行时范围检查**；
2. `STATE_MAX` 哨兵 + 名字表是枚举的标准工程模式；
3. `1<<n` 位标志枚举是权限/选项组合的通用解；
4. 配合 switch 且不写 default，让编译器帮你查漏分支；
5. 新增实测：枚举在机器码里**只剩立即数**（ERROR→40、FATAL→自动+1的41）——自动接续规则直接写在编译产物里。
