# 内联汇编

> 内联汇编（inline assembly）是在C代码里直接嵌汇编指令的机制——"通过汇编掌握C"的正面交汇点：知道每条指令在干什么的人，才有资格写它。
> 本页讲 GNU 扩展语法（gcc/clang通用）；MSVC 的 `__asm {}` 块风格不同但思想一致。
> 实测环境：Ubuntu 24.04 / gcc 13.3.0 / x86-64 / `-O2`

## 两种形态

```c
/* 基础内联：整块文本，无输入输出 */
__asm__ ("cli");                       /* 关中断（内核态才可用） */

/* 扩展内联：带约束的输入/输出 —— 真正的生产形态 */
__asm__ ("bswap %0" : "=r" (result) : "0" (value));
/*        指令模板   输出约束       输入约束
          %0指代result寄存器；"0"表示输入与第0个输出共用同一寄存器 */
```

## 扩展内联解剖：四个字段

```c
__asm__ __volatile__ (
    "指令模板 %0 %1"        /* ①模板：%N引用操作数 */
    : "=r" (out)            /* ②输出：=只写、+读写、=&独占（early-clobber） */
    : "r" (in1), "m" (in2)  /* ③输入：r=任意寄存器、m=内存、i=立即数、a/b/c/d=指定rax/rbx/rcx/rdx */
    : "memory"              /* ④clobber：通知编译器哪些被破坏 */
);
```

| 约束字符 | 含义 | 编译器行为 |
| --- | --- | --- |
| `r` | 任意通用寄存器 | 自由分配（实测里分到了eax） |
| `a`/`b`/`c`/`d` | 指定 rax/rbx/rcx/rdx | 硬绑（rdtsc必须a/d） |
| `m` | 内存操作数 | 直接给地址 |
| `i` | 立即数 | 编译期代入 |
| `=r` | 输出（只写） | —— |
| `"0"` | 与第0个输出同寄存器 | 输入复用输出槽（bswap同进同出） |

**`__volatile__` 的含义**：禁止编译器删除/移动/复制这段asm——**没有副作用的纯计算**（如bswap）可以不加；**有副作用**（rdtsc读计数器、MMIO写寄存器）必须加（对比[C语言变量·volatile](C语言变量.md)：同一关键字，同一天职）。

## 实测一：bswap —— 最小可用示例

```c
unsigned my_bswap(unsigned x)
{
    unsigned r;
    __asm__ ("bswap %0" : "=r" (r) : "0" (x));
    return r;
}
```

**真实编译产物**（gcc -O2，`#APP/#NO_APP`之间是gcc**原样嵌入**的文本）：

```asm
my_bswap:
    endbr64
    mov     eax, edi          ; 编译器：把x装进它选定的寄存器（恰好eax）
#APP
    bswap eax                 ; ★你的汇编文本，一字不改
#NO_APP
    ret                          ; r已在eax=返回值寄存器，白嫖返回约定
```

运行验证：`my_bswap(0x12345678) == 0x78563412 == __builtin_bswap32(0x12345678)` ✔

> 教训先行：**优先用 `__builtin_*` 内建函数**（bswap/clz/popcount都有）——可移植、编译器更懂如何优化；内联汇编是"没有内建可用"时的最后手段（读特殊寄存器、特权指令、极致优化）。

## 实测二：rdtsc —— 读时间戳计数器

```c
static inline unsigned long long rdtsc(void)
{
    unsigned lo, hi;
    __asm__ __volatile__ ("rdtsc" : "=a" (lo), "=d" (hi));
    /* rdtsc硬性约定：低32位→eax、高32位→edx —— 所以必须"a"/"d"硬绑 */
    return ((unsigned long long)hi << 32) | lo;
}

unsigned long long t0 = rdtsc();
/* 干活 */
unsigned long long t1 = rdtsc();
printf("%llu 周期\n", t1 - t0);   /* 实测：1000次空循环 ≈ 925周期 */
```

两处必懂：

1. **rdtsc 无操作数**、结果固定落 eax:edx——约束必须用 `"=a"`/`"=d"` 硬绑，`"=r"` 会读错寄存器；
2. 必须 `__volatile__`：两处rdtsc若被编译器"优化"成只读一次甚至对调，计时全毁。

## 实测三：cpuid —— 多输出的真实用法

```c
void cpu_vendor(char out[13])
{
    unsigned ebx, ecx, edx;
    __asm__ __volatile__ ("cpuid"
                          : "=b" (ebx), "=c" (ecx), "=d" (edx)
                          : "a" (0));        /* 输入：eax=0（厂商查询功能号） */
    memcpy(out,     &ebx, 4);               /* 厂商串12字符藏在ebx:edx:ecx */
    memcpy(out + 4, &edx, 4);
    memcpy(out + 8, &ecx, 4);
    out[12] = '\0';
}
/* 实测输出：cpu vendor = AuthenticAMD */
```

编译产物里的彩蛋：

```asm
cpu_vendor:
    endbr64
    push    rbx                  ; ★编译器自动保存rbx！
    xor     eax, eax             ; 输入a=0
#APP
    cpuid
#NO_APP
    mov     DWORD PTR [rdi], ebx ; 三个输出按约束分落到ebx/ecx/edx
    ...
```

**`"=b"`会破坏callee-saved的rbx**——扩展内联的第四字段（clobber）或指定输出约束后，**gcc自动插入push/pop rbx**保护调用约定（[通用寄存器](../汇编/通用寄存器.md)的知识在这里兑现）。这就是"编译器替你管寄存器分配"的全部含义：你声明约束，它负责搬运/保存/恢复。

## clobber："memory" 的含义

```c
__asm__ __volatile__ ("mfence" ::: "memory");
/* 第三个冒号后：告诉gcc——1)内存被这段asm读过/写过，缓存中的变量必须重新加载；
   2)指令顺序不得跨越此屏障重排 */
```

`"memory"` clobber = **编译器屏障**：多线程共享变量、MMIO访问的必备（完整内存屏障还需 `mfence/lfence/sfence` 硬指令——CPU级与编译器级是两回事）。

## 什么时候才该用内联汇编

| 场景 | 该用吗 | 替代 |
| --- | --- | --- |
| 位操作技巧 | ✘ | 运算符（[位运算](位运算.md)） |
| bswap/clz/popcount | ✘ | `__builtin_bswap32` 等 |
| 大部分"性能优化" | ✘ | 相信编译器 + profile |
| 读TSC/MSR/CR等特殊寄存器 | ✔ | 无内建 |
| 特权指令（内核） | ✔ | —— |
| 精确控制指令序列（屏障） | ✔ | `__atomic_*` / C11 `stdatomic` |

## 小结

1. 扩展内联四字段：**模板（%N引用）+ 输出约束 + 输入约束 + clobber**；
2. 约束是"委托书"：`r`让编译器选寄存器、`a/b/c/d`硬绑、`"0"`复用输出槽；
3. `__volatile__`防删防移——有副作用的asm必加；
4. 破坏callee-saved寄存器时gcc自动push/pop（实测cpuid的rbx）；
5. **先找内建函数，内联汇编是最后手段**——但读懂它=全库知识的综合考试。
