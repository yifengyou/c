# c-dev —— 汇编C语言知识库写作规范

## 本库核心逻辑（不可违背）

**通过汇编掌握C。**

1. C语言的一切概念最终都是**内存与指令**：
   * 变量 = 内存地址的别名；赋值 = `mov`；分支循环 = `cmp + jcc/jmp`；
   * 函数 = `call/ret + 栈帧`；数组 = 基址+变址×比例寻址；指针 = 间接寻址；
   * 结构体 = 编译期偏移表；const/常量区 = 段权限（rodata）。
2. 不了解体系结构就无法真正理解C——每个知识点都要回答：**"这在内存里长什么样？编译成什么指令？"**
3. 逆向视角贯穿始终：内容应有助于用 IDA/OllyDbg/DTDebug 静态动态分析（本库配套 crackme 实战）。

## 编译提取汇编的标准工作流

```bash
# 1. 写最小示例：一个知识点对应一个可编译的main（避免无关代码干扰输出）
#    示例放 /tmp/opencode/ 下做实验，最终汇编摘录进文档

# 2. 提取汇编（推荐参数）
gcc -S -O0 example.c -o example.s              # AT&T 语法（Linux默认）
gcc -S -O0 -masm=intel example.c -o example.s  # Intel 语法（贴近本库Windows逆向背景）
gcc -fno-asynchronous-unwind-tables ...        # 去掉 .cfi 噪音，输出更干净

# 3. 反汇编二进制（观察最终形态）
objdump -d -M intel a.out                      # 整个程序
gcc -c example.c && objdump -d -M intel example.o   # 只看本翻译单元

# 4. 对照优化
gcc -S -O2 example.c -o example_O2.s           # 对比学习：编译器会做什么

# 5. 验证行为
gcc example.c -o example && ./example; echo $? # 运行确认输出/退出码

# 6. 辅助工具
gcc -E example.c                               # 看预处理展开
size a.out                                     # 看 text/data/bss 段大小（验证内存分区章节）
nm/objdump -r example.o                        # 看符号与重定位（验证编译链接章节）
```

**摘录进文档时**：保留真实输出的关键行（可裁剪 `.cfi`/`.ident` 等噪音行，但不得改动指令本身），每行右侧或下方加中文注解；标注"实测环境"，例如：`实测：gcc 13.3.0 / x86-64 / -O0 / Intel语法`。

## 平台约定

* 实测以 **x86-64 Linux (System V ABI)** 为主：参数走 `rdi/rsi/rdx/rcx/r8/r9`，返回值 `rax`；
* 涉及 32 位差异（`ebp±偏移` 取参、cdecl 压栈传参）时明确标注"32位"；
* 段地址/栈布局是 Linux 典型布局，与 Windows（PE/SEH）的差异要提示。
